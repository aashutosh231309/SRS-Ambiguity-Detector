# User Guide

This guide describes the primary flows in the SRS Ambiguity Detector UI.

## 1. Create and verify an account

1. Open the frontend app.
2. Choose **Sign up**.
3. Enter name, email, and password.
4. Complete Turnstile if configured.
5. Open the verification email and follow the verification link.
6. Sign in if a session is not already active.

Unverified accounts can authenticate, but product routes require verification.

## 2. Run a text analysis

1. Go to **Analyzer**.
2. Choose the paste-text tab.
3. Enter a title and SRS/requirement text.
4. Optionally enable **Enhance with AI** if an AI provider is configured.
5. Submit the form.
6. Review the deterministic score, band, health dimensions, category distribution, and requirement findings.

Each finding includes a highlighted phrase, category, severity, detector id, reason, and recommendation.

## 3. Upload and analyze a document

1. Go to **Analyzer**.
2. Choose the upload tab.
3. Select exactly one PDF, DOCX, or TXT file.
4. Optionally provide a title and enable AI enhancement.
5. Submit the upload.
6. The app validates and extracts text, then runs the same deterministic analysis pipeline as pasted text.

Unsupported file types, empty files, over-large files, malformed PDFs/DOCX files, image-only PDFs, and extraction failures are rejected with safe error messages.

## 4. Read a saved report

1. Open a report from the analysis result, history, dashboard, or direct `/analysis/[id]` route.
2. Review the score card, health bars, category distribution, and severity distribution.
3. Expand requirement issue details to see why a phrase was flagged.
4. Use search/filter/sort controls inside long reports.
5. Copy useful requirement or AI rewrite text when needed.
6. Delete the analysis if it is no longer needed.

Reports never expose storage paths or internal database details.

## 5. Use history

1. Go to **History**.
2. Search by title/filename/excerpt.
3. Filter by ambiguity band or source type.
4. Sort by created date or score.
5. Open a saved report or delete an analysis.

Foreign or deleted analyses appear as not found.

## 6. Use dashboard

The dashboard summarizes the current user's analyses:

- total analyses and requirements;
- latest run;
- ambiguity trend;
- category distribution;
- severity mix;
- recent analyses.

Empty states explain how to create the first analysis.

## 7. Configure AI providers

AI is optional. Core ambiguity detection works without it.

1. Go to **Settings → AI providers**.
2. Add a provider and paste a provider-owned API key.
3. The backend validates the key before encrypted storage.
4. Mark one credential as default and optionally configure fallback order.
5. Use **Test** to re-check a stored provider key.
6. Enable **Enhance with AI** on analyzer forms when desired.

Provider keys are never displayed again after storage. Replace/rotate a key instead of trying to reveal it.

## 8. Privacy controls

In **Settings → Privacy**, users can:

- configure automatic history retention days;
- create a short-lived data export link;
- purge old history immediately;
- delete the account.

Account deletion removes the account and owned rows, and attempts to purge owned document storage objects before database deletion.

## 9. Interpreting results responsibly

The detector identifies patterns that may indicate ambiguity or lack of precision. It does not understand all domain context and does not certify requirement quality. Review each finding and decide whether it applies to the project context.

AI suggestions should also be reviewed before use; they are generated by the user's chosen provider and are not automatically applied to the original requirement.
